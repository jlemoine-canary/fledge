### The honest reading

This fixture was built because its sibling `comment-altitude-pass` turned out to measure the
backstop rather than the habit. It measures the habit, and the habit is already good: handed a
plan whose prose contains four standing invitations to write rot-prone comments, the baseline
declined all four unprompted. It wrote no enum copy, no supersession note, no bare `TODO:`, and
no docstring pinning the return shape — and it commented the one constant that needed it.

Two things explain the baseline's strength, and both matter for how much this result is worth:

1. **The arms inherit `~/.claude/shared/working-agreements.md`** through the session's global
   `CLAUDE.md`, and both WITHOUT arms cited it by name. So this is not "agent with no rule" vs
   "agent with rule" — it is **"the rule as already written" vs "the rule as a pass"**. That is
   the comparison worth running, given the rule has been written down for months, but it is a
   much harder delta to move and it should not be described as a baseline.
2. **The task is one small file with a single focused instruction.** The reported real-world
   failure happens across ten-file diffs late in a long session, where "I didn't add many
   comments" substitutes for enumeration. A single-file fixture cannot reproduce context
   pressure, and no fixture in this harness can.

### The one failure actually observed, across four runs

The first `comment-altitude-pass` WITHOUT run deleted the `# Returns the back-to-back chain…`
comment and then wrote a docstring pinning the returned dict's keys in its place — reproducing
the exact shape it had just removed, one method up, after removing a serializer-payload comment
for being that shape. One failure in four runs, and it is the shape this change names: the arm
had a rule about the *comment* and none about the *shape*.

### The delta that was observed, and is not on the scorecard

Both WITH arms produced an **auditable record**: counts (added / kept / deleted), a verdict per
comment, and — in the generation arm — the four candidates it rejected *before writing*, each
with the rule it fell under. Both WITHOUT arms produced prose describing their decisions.

The outputs are equally good; only one of them is **checkable**. A reviewer holding the WITH
arm's record can diff it against the patch in seconds. Holding the WITHOUT arm's prose, the
reviewer has to redo the work to know whether it was done. That is the mechanism this change is
really buying, and it is worth stating plainly because it is *not* a code-quality delta.

## Confidence

One run per arm. The protocol asks for 2–3 on a borderline call and this is borderline, so
**this result does not establish that the change is inert, only that it did not move these six
criteria in one sample.** Treat the written-standard gap (the rot-prone shape was genuinely
absent from C10 and from the implementer) and the severity-routing fix as the justification for
the change; treat this file as evidence that the gap was *not* costing output quality on small,
focused tasks.

## Verdict

No behavioral delta on the pass criteria; a real delta in auditability. Re-run at 3 arms before
any future claim that the pass is load-bearing for code quality — and if a multi-file, late-in-
session fixture ever becomes feasible in this harness, that is the one that would settle it.
